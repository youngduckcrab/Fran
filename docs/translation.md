# 번역 설계

번역기는 `server/src/translation/` 에 들어 있다. 이 문서는 **왜 그렇게 썼는지**와
**품질이 마음에 안 들 때 어디를 만지면 되는지**를 적어둔다.

```
translation/
  index.ts              provider 선택, 번역 실행, 사용량 기록
  prompt.ts             시스템/사용자 프롬프트 조립 (provider 공통)
  schema.ts             출력 JSON Schema + zod 검증
  providers/
    types.ts            provider 인터페이스
    gemini.ts           기본. 무료 티어
    claude.ts           유료
```

프롬프트와 스키마는 provider 와 무관하게 하나로 유지한다. provider 가 하는 일은
"시스템 프롬프트 + 사용자 프롬프트를 받아 JSON 문자열을 돌려주는 것" 하나뿐이라,
새 provider를 붙이려면 `TranslationProvider` 인터페이스 하나만 구현하면 된다.

## 이 번역이 일반 번역기와 다른 점

일반 번역기는 문장 하나를 받아 문장 하나를 낸다. 그래서 채팅에서 늘 두 가지가 깨진다.

1. **한국어·스페인어·중국어는 주어와 목적어를 마구 생략한다.** `"어제 걔가 그랬잖아"` 는 앞 대화를
   모르면 번역이 불가능하다. 그래서 직전 12개 메시지를 함께 넘긴다.
2. **말투가 사라진다.** `"ㅋㅋㅋㅋ 미쳤나봐"` 가 `"Ja, ja. Creo que está loco."` 로 오면 그건
   그 사람의 말이 아니다. 프롬프트가 가장 많은 분량을 쓰는 부분이 이 결.

## 프롬프트 구성

**시스템 프롬프트** (요청마다 거의 동일 → 프리픽스 캐시가 걸리도록 앞쪽에 둔다)

- 두 사람이 누구인지: 이름, 주 언어, 공부 중인 언어
- 공유 용어집 (`server/glossary.json`)
- 번역 규칙 9개
- 학습 메모를 언제 달지

**사용자 턴** (매번 바뀜)

- 직전 대화 기록 (시각, 이름, 언어, 원문)
- 번역할 메시지 — 삼중 따옴표로 감싸서 경계를 분명히
- 필요한 대상 언어 목록

**출력**은 JSON 스키마로 강제한다. 모델이 설명이나 사족을 붙일 자리가 아예 없다.
Gemini는 `responseJsonSchema` + `responseMimeType: 'application/json'`, Claude는
`output_config.format` 을 쓰지만 넘기는 스키마(`schema.ts`)는 같은 것이다.

스키마를 강제해도 모델 출력은 결국 외부 데이터라, DB에 쓰기 전에 zod로 한 번 더 검증한다.

```json
{
  "detected_lang": "ko",
  "translations": [
    { "lang": "es", "text": "…", "notes": [{ "term": "…", "meaning": "…" }] }
  ]
}
```

`detected_lang` 을 따로 받는 이유: 사용자가 공부하려고 평소와 다른 언어로 쓸 수 있다.
한국어 사용자가 스페인어로 한 줄 썼다면 스페인어로 다시 번역할 필요가 없다 —
서버가 `detected_lang` 과 같은 언어의 번역은 버린다.

## 규칙 아홉 개

프롬프트에 들어 있는 규칙을 요약하면:

1. 번역할 것은 마지막 메시지 하나뿐. 위쪽은 읽기만 한다
2. 격식 수준을 유지한다. 채팅을 문어체로 승격시키지 않는다
3. 이모지·말줄임·반복 글자·대문자·웃음을 살린다 (ㅋㅋㅋ ↔ jajaja ↔ hahaha ↔ 哈哈哈)
4. 생략된 주어·목적어는 맥락으로 복원하되, 없는 정보를 만들어내지 않는다
5. 관용구는 뜻으로 옮긴다. 대응 표현이 없으면 직역 대신 풀어 쓴다
6. 메시지가 하는 일을 옮긴다 — 농담은 농담으로, 투정은 투정으로
7. URL·숫자·이모지 하나처럼 번역이 필요 없는 건 그대로 둔다
8. `text` 는 메시지 그 자체다. 인사도 설명도 대안 번역도 붙이지 않는다
9. 성인 두 사람의 사적인 대화다. 애정 표현이나 거친 말도 세기를 낮추지 않고 그대로 옮긴다

## 학습 메모

번역마다 0~2개. 조건은 "학습자가 실제로 궁금해할 것"이다 — 직역이 안 되는 관용구, 슬랭,
문장이 걸려 있는 문법 포인트, 끝내 못 옮긴 뉘앙스. 평범한 문장에는 **아무것도 붙이지 않는다**.
메모가 매번 붙으면 읽기 싫어지고, 그러면 안 읽게 된다.

메모는 번역문의 언어로 쓴다. 스페인어 번역에 붙은 메모는 스페인어로 — 그것도 공부가 된다.

## 용어집

애칭·별명·둘만 아는 표현을 미리 정해두는 곳이다. 번역 규칙보다 우선한다.
채팅 화면 우상단 **용어집**에서 바로 편집하고, 저장하는 즉시 다음 번역부터 반영된다
(서버 재시작 불필요). 양쪽이 같은 용어집을 공유하며, 한쪽이 고치면 상대 화면도 갱신된다.

항목 하나는 세 가지를 담는다.

| 칸 | 뜻 |
| --- | --- |
| **표현** | 원문에 나오는 말. 예: `애기` |
| **이렇게 번역해 줘** | 언어별 지정. 예: es `bebe`. 전부 비우면 "번역하지 말고 그대로" |
| **이렇게는 쓰지 마** | 금지 표현. 예: `amor, cariño` |

금지 목록이 중요하다. `애기`는 스페인어로 `amor`, `cariño`, `bebe` 어느 쪽으로도 옮길 수
있고 모델은 그때그때 다르게 고른다. 둘 사이에서 `amor` 가 어색하다면 그건 번역 품질 문제가
아니라 **취향**이고, 모델이 알 수 없는 정보다. 적어두면 그 단어를 피해서 옮긴다.

`server/glossary.json` 은 이제 **처음 켤 때 한 번만** DB 로 옮겨 담는 씨앗이다.
그 뒤로는 DB 가 원본이므로 파일을 고쳐도 반영되지 않는다.

## 이번 메시지에만 붙이는 지시

미리 정해둔 규칙을 그때그때 덮어쓰고 싶을 때가 있다. 평소엔 `애기` → `bebe` 지만
오늘은 `amor` 라고 불러보고 싶은 경우.

입력창 왼쪽 **✎** 버튼을 누르면 한 줄짜리 지시 칸이 열린다. 거기에
`amor 로 표현해줘` 라고 적고 메시지를 보내면 그 메시지에만 적용되고, 보낸 뒤 지워진다.
말풍선의 **다시 시도**로 지시를 바꿔 다시 번역할 수도 있다.

**이 지시는 상대에게 전달되지 않는다.** 화면에서 숨기는 정도가 아니라, 서버가 상대에게
보내는 payload 에서 아예 빼고 보낸다. 재접속해서 대화 기록을 다시 받아도 마찬가지다.
프롬프트에도 "지시를 언급하지 말라"고 못박아 두었으므로 번역문이나 메모에 흔적이 남지 않는다.

지시와 용어집이 부딪히면 지시가 이긴다. 일부러 한 번 다르게 해보는 것이기 때문이다.

## Gemini 설정

| 환경변수 | 기본값 | 뜻 |
| --- | --- | --- |
| `GEMINI_MODEL` | `gemini-flash-lite-latest` | 무료 한도가 가장 넉넉한 쪽. 품질을 올리려면 `gemini-flash-latest` (한도는 줄어든다) |
| `GEMINI_THINKING_BUDGET` | (안 보냄) | 적어 두면 그 값으로 보낸다. 0은 사고 끄기, -1은 자동. **이 파라미터를 받지 않는 모델이 있고, 보내면 요청 전체가 `INVALID_ARGUMENT` 로 거부되므로** 기본값은 아예 보내지 않는 것이다 |
| `GEMINI_SAFETY_THRESHOLD` | `BLOCK_NONE` | 아래 참고 |

**안전 필터를 왜 내리나.** Gemini는 기본적으로 성적·공격적 표현을 차단하는데, 연인끼리
주고받는 애정 표현이나 장난스러운 욕설이 여기 걸리면 **번역이 통째로 막힌다**. 원문은 이미
상대에게 도착해 있는데 번역만 안 되는 상황이 생긴다. 사적인 1:1 번역에는 맞지 않는 기본값이라
`BLOCK_NONE` 으로 내려둔다. 계정에서 이 값을 거부하면 `BLOCK_ONLY_HIGH` 로 올리면 된다.

## 문장 설명 (학습용)

말풍선을 **길게 누르면** 메뉴가 뜨고, **설명**을 고르면 그 문장을 뜯어서 보여준다.
이 앱이 단순 번역기와 갈라지는 지점이다 — 번역문만 읽으면 뜻은 알아도 다음에 내가
그렇게 말할 수는 없다.

설명은 네 덩어리로 나온다.

| 칸 | 내용 |
| --- | --- |
| 요약 | 이 문장이 결국 무슨 말인지 한 줄. 직역이 아니라 사람이 말하는 뜻 |
| 조각 | 의미 단위로 자른 뒤 각각의 뜻. 한글·한자는 읽는 법(로마자·병음)도 |
| 짚고 갈 점 | 이 문장이 보여주는 문법 패턴, 말투, 번역이 못 옮긴 뉘앙스 (1~3개) |
| 이렇게 답할 수 있어요 | 그 언어로 된 자연스러운 답변 1~2개 |

마지막 칸이 중요하다. 대화하면서 배우는 앱이니 **답할 수 있어야** 의미가 있다.

**어느 문장을 설명받을지 고를 수 있다.** 메시지 하나에는 원문과 번역문들이 함께 있는데,
공부하려는 언어가 사람마다 다르기 때문이다. 스페인어를 공부하는 승윤에게는 Fran 이 보낸
스페인어 원문이, 한국어를 공부하는 Fran 에게는 승윤의 한국어 원문이 기본으로 열린다.
영어도 켜두었다면 같은 메시지의 영어 번역을 골라 설명받을 수 있다.

설명을 쓰는 언어는 읽는 사람의 주 언어다. 조각별 `note` 는 배울 게 있을 때만 붙고,
평범한 단어에는 붙지 않는다. 짧은 문장에는 짧은 설명이 맞는 설명이다.

한 번 만든 설명은 `explanations` 테이블에 (메시지, 대상 언어, 설명 언어) 단위로 저장된다.
같은 문장을 다시 열어도 모델을 다시 부르지 않는다.

## 무료 티어 할당량

429 는 두 종류이고 대응이 다르다. Google 이 응답에 어느 쪽인지 알려주므로 그대로 구분해서
보여준다.

| 종류 | 화면에 나오는 말 | 동작 |
| --- | --- | --- |
| 분당 한도 | `분당 요청 한도를 넘었습니다. 27초 뒤…` | 알려준 시간만큼 기다렸다 **한 번만** 재시도 |
| 하루 한도 | `오늘 쓸 수 있는 무료 요청을 다 썼습니다…` | 재시도하지 않음 |

분당 한도에서 여러 번 두드리면 한도만 더 깎이므로 재시도는 한 번으로 제한한다.
하루 한도는 날이 바뀌어야 풀리니 재시도가 의미 없다.

**요청은 언제 나가나.** 메시지 한 통에 번역 1회(대상 언어가 몇 개든 한 번), 설명 1회
(같은 문장·같은 언어는 저장해 두고 다시 부르지 않는다). 테스트하며 메시지를 연달아 보내면
분당 한도에 쉽게 닿는다. 터미널의 `[usage] ... 누적 N회` 로 지금까지 몇 번 썼는지 볼 수 있다.

**모델을 바꾸면 한도도 바뀐다.** 대체로 `lite` < `flash` < `pro` 순으로 한도가 줄고 품질이
오른다. 기본값을 `gemini-flash-lite-latest` 로 둔 것은 둘이 쓰는 앱에서 한도에 걸려 번역이
멈추는 쪽이 번역이 조금 밋밋한 쪽보다 나쁘기 때문이다. 대화가 자리를 잡고 한도에 여유가
생기면 `gemini-flash-latest` 로 올리면 된다.

```bash
npm run models --workspace=server
```

지금 쓰는 모델에 `→` 가 붙고, 한도가 넉넉한 쪽이 위에 온다. 정확한 한도 숫자는 API 가
알려주지 않으므로 [AI Studio](https://aistudio.google.com) 에서 확인해야 한다.

## 비용과 속도

한 메시지당 호출 한 번. 입력은 시스템 프롬프트(대략 700~900 토큰) + 직전 12개 대화,
출력은 번역문과 메모 정도라 보통 수백 토큰이다.

**사용량은 로그에 남는다.** 번역할 때마다 이런 줄이 찍힌다:

```
[usage] gemini/gemini-flash-latest in=1243 out=118 412ms | 누적 37회 in=44982 out=4166
```

무료 티어를 쓰는 동안에는 이게 "한도에 얼마나 가까운지"를 보는 용도이고,
유료로 넘어갈 때는 그대로 비용 계산에 쓰면 된다.

- **`TRANSLATION_CONTEXT_SIZE`** 를 키우면 대명사 해석이 좋아지지만 매 호출 입력이 늘어난다.
  12는 "방금 무슨 얘기 중이었는지"를 담기에 충분한 정도
- Claude provider는 시스템 프롬프트에 `cache_control` 을 붙여 캐시를 노린다. 다만 프롬프트가
  짧으면 최소 캐시 길이에 못 미쳐 캐시가 안 걸릴 수 있다. 로그의 `cached=` 로 확인 가능

### 유료로 넘어간다면

`TRANSLATION_PROVIDER=claude` 로 바꾸고 `ANTHROPIC_API_KEY` 를 넣으면 된다.
Claude 구독(Pro/Max)에는 API 크레딧이 포함되지 않으므로 별도 결제가 필요하다.
대략적인 단가는 메시지당 Haiku 4.5 기준 $0.002, Sonnet 5 기준 $0.004 수준이다(추정).

`CLAUDE_EFFORT` 는 `low` 가 기본이고 `max` 까지 올릴 수 있다. 단 **Haiku 계열은 이 파라미터를
받지 않아서** 모델 이름에 `haiku` 가 들어가면 자동으로 생략한다. `off` 로 명시해도 된다.

## 품질이 마음에 안 들 때

| 증상 | 손볼 곳 |
| --- | --- |
| 말투가 너무 딱딱하다 | 프롬프트 규칙 2·3을 강화하거나, 실패한 예시를 프롬프트에 넣는다 |
| 대명사를 자꾸 틀린다 | `TRANSLATION_CONTEXT_SIZE` 를 늘린다 |
| 애칭·별명을 번역해 버린다 | `glossary.json` 에 추가 |
| 메모가 너무 많다 / 뻔하다 | "Learner notes" 문단의 기준을 더 좁힌다 |
| 전반적으로 아쉽다 | 더 큰 모델로. Gemini는 `GEMINI_MODEL` 을 Pro 계열로, 또는 `TRANSLATION_PROVIDER=claude` |
| 번역이 자꾸 안전 필터에 막힌다 | `GEMINI_SAFETY_THRESHOLD` 확인. 로그에 `SAFETY` 나 `PROHIBITED_CONTENT` 가 찍힌다 |
| `429` / 할당량 초과 | 아래 참고 |

프롬프트를 손볼 때는 **실제로 주고받은 메시지 중 번역이 어색했던 것 10~20개를 모아두고**
바꾸기 전후를 비교하는 게 가장 빠르다. 느낌만으로 프롬프트를 고치면 한쪽을 고치다 다른 쪽이 깨진다.

## 실패했을 때

**일시적인 실패는 먼저 스스로 다시 해본다.** 모델 과부하(503 `UNAVAILABLE`)나 네트워크
장애는 흔하고 대개 몇 초면 풀리므로, 1초 → 3초 → 8초 간격으로 세 번까지 재시도한다.
원문은 이미 상대에게 도착해 있어서 몇 초 늦는 것은 문제가 되지 않는다.

재시도하지 않는 것도 있다. 키가 틀렸거나(`API_KEY_INVALID`) 모델 이름이 없거나(`404`)
할당량을 넘긴(`429`) 경우는 몇 번을 해도 결과가 같다. 특히 할당량은 분당 한도인지 하루
한도인지 구분할 수 없어서, 괜히 재시도해 한도를 더 깎는 대신 사용자에게 알린다.

세 번을 다 써도 실패하면 메시지가 사라지는 게 아니라 `translation_status` 가 `failed` 가
되고, 원문과 함께 **실패 이유가 말풍선에 표시된다.** 상대는 서버 로그를 볼 수 없으므로
화면에서 이유를 알 수 있어야 한다. "다시 시도"를 누르면 그 메시지만 다시 번역한다.

모델이 거절하거나 안전 필터에 막히는 경우도 같은 실패로 처리하고, 서버 로그에 사유가 남는다.
무료 티어 할당량 초과(`429`)와 모델 이름 오타(`404`)는 로그에 무엇을 해야 하는지까지 적어둔다.

번역 실패 시 다른 provider로 자동 전환하는 폴백은 넣지 않았다. 원문은 이미 상대에게
도착해 있어서 급할 게 없고, 조용히 다른 모델로 넘어가면 어떤 모델이 번역했는지 알 수 없게 된다.
대신 실패한 메시지는 "다시 시도" 버튼으로 직접 다시 돌릴 수 있다.
